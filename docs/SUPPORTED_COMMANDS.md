# Blot Firmware — Supported G-code

(disclaimer: these docs are generated by Claude and used for reference by it. It is accurate, feel free to read it!)

The only way to print is a job uploaded through the web UI — there is no USB or serial input. The parser accepts exactly what the web UI's generators emit (`convert.js` from amazinaxel.com, the sticker tool), and nothing more.

Every line of a job is one of three things:

| Outcome     | When                                                                 |
| ----------- | -------------------------------------------------------------------- |
| **run**     | supported (below)                                                    |
| **skipped** | unsupported but harmless: no geometry (`G17`, `G64`, `M18`, `M30`...) |
| **error**   | malformed, out of the work area, or would draw in the wrong place if ignored — **the print stops** and returns to where it started, pen up |

Stopping beats carrying on: a skipped arc or an ignored unit change would leave the rest of the drawing silently mangled.

## Supported

| Code  | Words   | Meaning                                                        |
| ----- | ------- | -------------------------------------------------------------- |
| `G0`  | `X Y`   | Move at the rapid cap `$111` (pen-up travel)                   |
| `G1`  | `X Y F` | Move at feedrate `F` (mm/min, modal)                           |
| `G21` |         | Millimetres — the only unit, so a no-op                        |
| `G90` |         | Absolute coordinates — the only mode, so a no-op               |
| `G92` | `X Y`   | The current position becomes the given work coordinates        |
| `M3`  |         | Pen down (`$151` pulse width)                                  |
| `M5`  |         | Pen up (`$150` pulse width)                                    |
| `M0`/`M1` |     | Pause the job; resume from the web UI                          |
| `;` `( )` |     | Comments                                                       |

- A missing `X` or `Y` keeps that axis where it is; zero-length moves are dropped.
- Pen commands are queued with the motion, so they happen at the right point in the path, after the moves before them have finished. The machine waits ~60 ms for the pen to arrive, and stops pulsing the servo 400 ms later so it doesn't buzz.
- At most two M-codes per line.
- A line is at most 95 characters; anything past that is an error unless it's whitespace or the rest of a `;` comment.
- Numbers are plain decimals: optional sign and fraction, no exponent or hex.
- `$` lines in a job are skipped: settings belong to the web UI.

## Errors (the print stops)

- A move outside the work envelope (`$130`/`$131`, while soft limits `$20` are on). Limits are in **machine** coordinates — measured from where the pen sat at power-on — so a `G92` origin far across the bed shrinks the drawable area.
- `G2`/`G3` (arcs), `G20` (inches), `G91` (relative), `G28`/`G30` (go home), `G53` (machine coordinates), and any decimal code (`G92.1`, `G61.1`...).
- A malformed word, a negative `F`, two motion codes on one line, more than four G-codes or two M-codes on one line.

## Motors and power

There are no motor commands. Jobs energise the motors when they start; once the machine is idle with no job (finished or stopped) the motors are released, and the CPU drops to 80 MHz until the next motion. A paused job keeps holding position.

## Settings

Settings are set by the web UI (the quality presets today; the calibrator later — see [CALIBRATION.md](CALIBRATION.md) for the full list and what each one means). They persist to flash, and an unchanged value is never rewritten.
